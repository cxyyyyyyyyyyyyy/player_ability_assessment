# 调研报告

> 调研现有球员能力评估 / 数据分析工具、数据集与技术路线。

## 一、调研目标

在正式开发前明确三个问题：
1. 市面上已有哪些球员评价体系与工具，各自的思路和局限是什么；
2. 可用的公开足球数据集有哪些，规模、字段与获取成本如何；
3. 本项目应采用的技术路线（语言 / Web 框架 / 算法库）与理由。

## 二、相关产品与工具调研

| 工具/体系 | 方式 | 优点 | 局限 |
|-----------|------|------|------|
| EA Sports FC（FIFA） | 官方评分 + 六维能力 | 覆盖面广、大众认知度高 | 黑盒、不解释依据；无生涯维度 |
| Football Manager | 球探工具 + 隐藏能力 | 数据专业 | 闭源收费，数据不可导出 |
| SciSports / Opta 分析 | 专业追踪数据建模 | 科学、商用成熟 | 收费高、面向职业俱乐部 |
| WhoScored / SofaScore | 比赛统计聚合评分 | 数据透明 | 反映近期表现而非潜力 |
| 虎扑/懂球帝球员评分 | 用户打分 | 互动性强 | 主观性强、噪声大 |

**结论**：本课程项目应自建「输入球员资料 → 聚类定位 + 回归预测潜力 + 相似度匹配」的透明可解释路线，避免依赖不可获得的商业数据。

## 三、数据集调研

| 数据集 | 规模 | 字段 | 获取 | 评估 |
|--------|------|------|------|------|
| European Soccer Database | SQLite 313MB，约 2.5 万球员 | 六维能力、年龄、位置、身价、潜力 | 开源下载 | 字段完整，适合建模；体积大 |
| Kaggle FIFA 24 Complete Player Dataset | 约 1.7 万球员 | 六维、潜力、身价、工资 | Kaggle 下载 | 与 EA 体系一致，可直接映射能力值 |
| 手工整理球星库（32 名） | 小 | 同上 | 团队整理 | 用于演示与对标，可信可控 |

**结论**：以 European Soccer Database 为主数据源，通过一次性提取脚本生成 `star_players.csv`（球星库）与 `player_pool.csv`（球员池，约 1800 人）；运行时只读 CSV，不依赖大文件 SQLite。

## 四、技术选型对比

| 维度 | 备选 | 选择与理由 |
|------|------|-----------|
| 语言 | Python / Java / JS | Python：数据科学生态最全 |
| Web 框架 | FastAPI / Flask / Django | FastAPI：异步、自带 OpenAPI 文档、类型校验，适合 AI 服务 |
| 前端 | 原生 HTML/CSS/JS / Streamlit | 原生为主：可定制、由后端统一托管；Streamlit 供快速原型 |
| 聚类 | KMeans / DBSCAN / 层次聚类 | KMeans：适合大规模样本、可解释，配合 PCA 可视化 |
| 潜力回归 | 随机森林 / 线性回归 / LightGBM | 随机森林：无需归一化、抗过拟合、可输出特征重要性 |
| 相似度 | 余弦相似度 / 欧氏距离 | 余弦：对量纲不敏感，适合能力向量匹配 |
| OCR | RapidOCR / PaddleOCR / Tesseract | RapidOCR：onnx 推理快、离线可用、中文识别好 |
| 文本增强 | 规则引擎 / LLM | 规则引擎兜底，LLM 可选增强，避免依赖付费接口 |

## 五、调研结论

1. 项目采用 **Python + FastAPI + scikit-learn + 原生前端** 的技术栈完全可行，团队 5 人可在一周内完成闭环；
2. 数据层面采用「公开大库一次性提取 + 本地 CSV 常驻」策略，兼顾真实性与工程可交付性；
3. 核心差异化在于**透明可解释**：六维画像、聚类风格、潜力曲线、相似球星全部有据可查；
4. 风险点与对策：数据字段口径不统一 → 统一 position/overall 映射；模型指标说服力 → 报告 R²、RMSE；LLM 依赖 → 规则引擎兜底。
